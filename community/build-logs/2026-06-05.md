# Bizbox Build Log — Week of 2026-06-01

Five PRs merged (2026-05-31 through 2026-06-03), four releases shipped. The headline: Workflows land as a first-class Bizbox primitive — company-scoped, ADK-backed, with topological pipeline graphs, live console output, and human handoffs. Alongside that: the ClickUp bridge adapter closes the awaiting-human approval loop end-to-end, a critical fix to Google ADK instruction parsing, suggested-task deduplication to prevent ghost child issues, and a CI stabilisation for headless e2e runs.

*Release tags this week: v2026.601.0 (PRs #72, #74, #76, #78, #84), v2026.602.0 (PRs #83¹, #88), v2026.602.1 (PR #87), v2026.603.0 (PR #86).*

## Shipped This Week

### 🔄 Workflows: a new company-scoped primitive
**PR [#86](https://github.com/zesthq/bizbox/pull/86) · @DennisDenuto · merged 2026-06-03 · v2026.603.0**

The largest change this week introduces `Workflows` as a distinct Bizbox primitive, separate from issues and routines. A workflow is a multi-phase pipeline backed by Google ADK: it has a database record, run history, deliverables, and a UI that renders phases as a topological graph with live phase state and console output.

Key additions:
- New DB schema, API routes, and JWT-protected runtime callbacks for workflow runs.
- ADK project analysis so the pipeline structure is inferred automatically and rendered as a graph.
- Human handoff slots within a pipeline run — agents can pause and wait for operator input without blocking the whole workflow.
- Mixed deliverable support: a single workflow run can surface structured data, documents, and raw console output side by side.
- UI navigation, workflow detail/run views, and pipeline graph rendering.

This is the first step toward long-running, multi-agent orchestration that doesn't fit neatly into the issue/heartbeat model.

### 🔌 ClickUp bridge adapter: awaiting-human loop closed end-to-end
**PR [#78](https://github.com/zesthq/bizbox/pull/78) · @ralphbibera · merged 2026-05-31 · v2026.601.0**

PR #78 ships the ClickUp transport as a provider-agnostic plugin, completing the full approval loop: company settings → bridge core → ClickUp → human reply → agent wake. The adapter is pure plugin architecture — no coupling to the core bridge runtime. This is the capstone of the awaiting-human bridge milestone that was waiting on a tagged release; v2026.601.0 is that release.

### 🐛 Google ADK: strip frontmatter from AGENTS.md instructions
**PR [#87](https://github.com/zesthq/bizbox/pull/87) · @ralphbibera · merged 2026-06-02 · v2026.602.1**

YAML frontmatter in `AGENTS.md` is used by Paperclip for metadata and discovery — but the Google ADK adapter was passing the raw file (frontmatter and all) as agent instructions. ADK treated the YAML block as part of the instruction text, producing garbled prompts for ADK-backed agents. The fix strips frontmatter before forwarding instructions to the ADK runtime. Simple change, material impact on ADK agent behaviour.

### 🔂 Issue origin handling with suggested-task deduplication
**PR [#88](https://github.com/zesthq/bizbox/pull/88) · @adPalafox · merged 2026-06-02 · v2026.602.0**

Accepting the same `suggest_tasks` interaction bundle multiple times used to create duplicate child issues. This PR fixes that with SHA-256 fingerprinting: if a matching child issue already exists, the service reuses it instead of creating a duplicate. Blocker relationships are preserved on reuse. The change adds `"suggested_task"` as an explicit `originKind` constant so the dedup path is unambiguous at the data layer, and broadens issue origin handling across the board.

### 🧪 CI: headless Chrome on runner for e2e workflows
**PR [#84](https://github.com/zesthq/bizbox/pull/84) · @ralphbibera · merged 2026-06-01 · v2026.601.0**

E2e tests for headless control-plane workflows were timing out on CI due to browser bootstrap latency, not application logic. Switching to the runner's native Chrome instance eliminates the cold-start delay and restores green e2e coverage.

## Decisions

**Workflows are a primitive, not a plugin.** The team built `Workflows` into the Bizbox data model (new DB tables, API routes, shared contracts) rather than layering them on top of routines or issues. Workflows need their own run lineage, deliverable surface, and pipeline graph that existing primitives can't cleanly host. The trade-off is more surface area to maintain.

**ADK pipeline structure inferred, not declared.** Rather than requiring operators to declare the pipeline graph upfront, PR #86 adds ADK project analysis so the phase structure is inferred from the ADK project definition at run time. This reduces operator configuration but means the graph is only as accurate as ADK's own project metadata.

**Fingerprint-based deduplication over timestamp guards.** SHA-256 fingerprinting of the full task spec (not a simple title check or timestamp window) was chosen for suggested-task dedup. The stronger guarantee is worth the extra hashing overhead at issue-creation time.

---

## Trade-offs

- **Workflows ship without end-to-end integration tests.** PR #86 includes server, shared, and UI unit tests plus local verification, but there is no automated test covering the full path: workflow create → ADK run → phase graph render → human handoff → deliverable surface. This is a non-trivial reliability risk for early adopters.
- **Fingerprint deduplication is strict.** A suggested task that differs by even one field (e.g. priority bumped) will create a new child issue rather than reusing the existing one. Correct, but may surprise operators who expected a looser match.
- **v2026.601.0 bundles last week's untagged PRs.** PRs #72, #74, and #76 (merged 2026-05-28) finally shipped in a tagged release this week. If you were waiting on a stable tag for the awaiting-human bridge or Google ADK adapter, v2026.601.0 is it.

## Open Challenges

- **Release CI failures — two this week.** The Release workflow failed twice: after the ADK frontmatter fix (#87) pushed v2026.602.1 ([run #26806281211](https://github.com/zesthq/bizbox/actions/runs/26806281211), 2026-06-02), and again after the Workflows PR (#86) merged v2026.603.0 ([run #26858452717](https://github.com/zesthq/bizbox/actions/runs/26858452717), 2026-06-03). Two Release failures in a week is a pattern worth an immediate investigation to confirm release artefacts are sound.
- **Workflows end-to-end test gap.** The pipeline graph, human handoff, and deliverable surface are all new and not yet covered by automated integration tests. A non-trivial reliability risk for early adopters.
